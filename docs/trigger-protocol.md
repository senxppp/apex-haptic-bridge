# 协议速查（观察结果）

> 全部来自对实际 USB 流量的观察与实机标定，不是厂商文档。
> 字节位置固定可靠；**语义**部分只有 mode 1 / mode 2 被实机验证过，其余为推断。

## 帧外壳

```
03 5A A5  |  cmd  |  len  |  payload ...  |  填充  |  checksum
```

- 前 3 字节是魔数，恒定。
- `cmd`：`0x12` 电机电平 / `0x51` 扳机状态 / `0x53` 流使能
- `checksum` = `sum(bytes[2..30]) & 0xFF`（从魔数第二字节算到倒数第二字节），放在最后一字节。
  `0x12` 这类短帧不带校验。

## 0x12 — 电机电平

```
03 5A A5 12 04 low high        （7 字节）
                    └──┬──┘
                       └─ 低/高电平，各 0..255，左/右握把
```

**电平保持型**：写一次就一直转，直到被下一帧覆盖。所以流一断必须有人写零，
否则马达会永远转。这是整个项目里最容易忘的一条。

> 长度字段是 `0x04` 但后面只有 2 字节载荷——实测固件按固定偏移取值。
> 别去"修正"它，改了就不工作。

## 0x51 — 扳机状态（SetForceTrigger）

32 字节定长：

```
偏移   值                含义
0-2    03 5A A5          魔数
3      51                命令
4      08                载荷长度
5      01                apply（固定 1）
6      side              1=左 2=右
7      mode              见下表
8      start             起始位置 0..192
9      p1                主参数
10     p2                次参数
11     p3                第三参数
12     match             0
13-30  00                填充
31     checksum          sum(bytes[2..30]) & 0xFF
```

**状态设定命令，不是流**。设一次就保持，不需要每帧刷——这也意味着落下之后
必须有人负责收回来。

| mode | 语义（实机验证） | 参数有效性 |
|---|---|---|
| 0 | 常规 / 释放 | `start` = 行程 |
| 1 | 阻尼（赛车） | **`p1` = 阻尼力度 1..255** ✅ 实机可分档（1 / 8 / 32 / 120 / 255） |
| 2 | 机枪抖动 | `p2` = 强度（实测有效 55..200）、`p3` = 频率档（45..70） ✅ |
| 3 | 狙击（突破） | 未验证 |
| 4 | 扳机锁 | 未验证 |
| 5 | 扳机震动 | ❌ 实机完全无响应，这支固件不实现 |

> `mode 1` + `p1=1` 是"最轻的持续阻力，从第 0 毫米就开始"。这就是"常态"，
> 也是回落目标——**回落必须和开机初始化用同一组字节**。

### 一个坑：`max(1, ...)`

便利构造函数会把 `p1/p2/p3` 抬到最小 1：

```python
payload = bytes([1, side, mode, start, max(1, p1), max(1, p2), max(1, p3), match])
```

所以"释放"（`p2=0,p3=0`）不能走这个函数，得手工拼字节。否则回落出来的"常态"
比开机常态更硬，表现为**音乐停了扳机还在震**。`k5_trigger_rest()` 就是为此存在的。

## 0x57 — 引擎实时帧

```
5A A5 57 len pkgCount | 24 字节样本 + 1 字节填充 | checksum
```

24 字节 = **8 个子帧 × 3 通道**，每通道线上编码 `i8 + 128`（`0x80` = 0）：

```
子帧 i:  [ t , l , r ]        i = 0..7
          │   │   └─ 右握把
          │   └───── 左握把
          └───────── 扳机
```

- 帧率 125 Hz → 8 子帧 = 每秒 1000 个采样点
- 每通道取 8 个样本的 RMS，再映射到 0..255 的电平
- **没有 flags 字节**（早期按"有 flags"解析，结果三通道全部错位）

## 扳机的两种物理量

目标手柄的扳机是力反馈电机，不是音频马达。这个差别决定了不能说"振动波形"：

| 想要的 | 电机能做的 | 做法 |
|---|---|---|
| 抖一下 | ✅ | `mode 2`，`p2` 给强度 |
| 顶手变紧 | ✅ | `mode 1`，`p1` 给力度 |
| 高频振动 | ❌ | 60/80/130 Hz 载波对电机等于噪声，必须降到"力" |

所以音频侧的 DSP 只取**包络**，丢掉载波：

```
包络 ──┬─→ mode 2 强度/频率     （瞬态、打击）
       └─→ mode 1 力度          （持续音、氛围）
```

## 怎么自己标定

`trig_lab.py` 是个独立标定台，会自己临时关掉主链路的爆发层（避免抢扳机）、跑完还原：

```bash
python trig_lab.py --pads                 # 先看手柄在哪个 XInput 槽
python trig_lab.py --seq damp             # mode 1：力度 × 起始位置矩阵
python trig_lab.py --seq vib5             # mode 5：看固件到底认不认
python trig_lab.py --manual 2 1 0 55 200  # 手搓一帧：mode=2 side=1 start=0 p2=55 p3=200
```

每组之间留 0.7 s 间隔，终端打序号——**扳机是纯输出执行器，没有回读**，
参数只能靠手感判。这也是为什么这东西必须有个人在旁边按着试。
