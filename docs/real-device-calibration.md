# 真机标定清单（7 天窗口内该做的事）

> 前提：真机只是**临时参照物**，不是要拆的东西。
> 因此本清单全部是**非侵入式**操作：USB 抓包 + 手感对照 + 录数据。
> 不拆机、不刷固件、不改固件、不撬外壳——既能保住退货资格，也能拿到九成价值。

## 0. 为什么值得借一台真机

现在这套参数全部是**从帧结构推出来的**，没有一次是「跟真机比出来的」：

| 参数 | 现值 | 依据 |
|---|---|---|
| `tr_p2_max` | 200 | 协议强度域的上沿 |
| `tr_head_ms` | 30 | 抄的四段结构里的头衰减 |
| `tr_release_ms` | 220 | 试出来的，觉得"黏"就加 |
| `tf_max` | 120 | 猜的（而且这一层默认关着） |

真机的价值有两个，第二个常被忽略：

1. **手感基准**：同一段声音，真机是什么形状，我们差在哪一格
2. **设备侧行为**：`0x51` 从发出到扳机建立的实际延迟、`0x12` 到马达起转的延迟、
   以及**真机主动上报了什么帧**——这部分我们现在是"编"的，从来没有对照过

第 2 点里有一条真实风险：如果引擎依赖某个我们没实现的设备主动上报，
我们只是"碰巧能用"。抓一次真机双向会话就能确认。

## 1. 准备（半小时）

```bash
# 抓包：Wireshark + USBPcap，只抓目标设备的端点
#   过滤：usb.idVendor == 0x37D7
#   需要同时看到 IN 和 OUT，所以别用"只抓本机"以外的精简模式
```

记录工具：一个表格（见第 4 节），一段固定音频集（见第 2 节）。
音频要**同一份文件**，两次播放用的是同一个播放器和同一个音量——否则测的是音量不是手感。

## 2. 六段对照音频

按顺序放，每段放两遍：先真机，再我们的链路（或反过来，别记住顺序，避免先入为主）。
听完立刻在表格里打分，别攒到最后回忆。

| # | 素材 | 想测的是 | 真机该有的特征 |
|---|---|---|---|
| 1 | 单次金属敲击（打铁） | 起振速度、脆度 | 一下就到位，没有"渐强" |
| 2 | 连续 4 次敲击，间隔 120 ms | 连打是否连成一片 | 四次能分开数清 |
| 3 | 低频鼓点（60~80 Hz） | 低频走握把还是扳机 | 应该主要在握把，扳机不该抢 |
| 4 | 持续弦乐（3 秒不断） | 持续音的手感 | 有底噪感但不"卡顿" |
| 5 | 白噪爆发 50 ms 后骤停 | 释放快慢 | 停得干净，没有拖尾 |
| 6 | 静音 2 秒 | 回到常态要多久 | 应该几乎立刻安静 |

## 3. 设备侧要抓的四组数据

抓包时对照着做，每组做完在 Wireshark 里量时间差：

| 项 | 怎么测 | 要记的数 |
|---|---|---|
| A. 完整描述符 | 插上真机，`lsusb -v` 或 Wireshark 的设备描述符 | 配置/接口/端点/字符串/BOS 全套，跟虚拟设备的对一遍 |
| B. 设备主动上报 | 不操作、只插着，录 30 秒 | 有没有我们不认识的 IN 帧？周期多少？ |
| C. `0x51` 建立延迟 | 手放扳机上，触发一次模式切换 | 从 OUT 帧到"手感出现"的实际时间（秒表粗测即可） |
| D. `0x12` 起转延迟 | 给一个阶跃电平 | 从 OUT 到马达开始转的时间 |

D 这一项会直接影响 `k5_min_iv`：如果真机的起转延迟明显小于 20 ms，
说明我们的写入间隔还有压缩空间；如果更大，说明 0.08 s 已经很宽松。

## 4. 记录表

```
素材  |  真机  |  我们的  |  差异方向  |  可能要改的键
------+--------+----------+------------+------------------
  1   | 脆/闷  |          |            | tr_head_ms
  2   | 分得开 |          |            | tr_lockout_ms
  3   | 位置   |          |            | （路由问题，非参数）
  4   | 顺/卡  |          |            | tr_release_ms
  5   | 拖尾   |          |            | tr_body_hold_ms
  6   | 静默   |          |            | tf_base / tr_release_ms
```

## 5. 判读规则（差异 → 改哪个键）

| 现象 | 原因 | 改法 |
|---|---|---|
| 我们的起振"软"，没有那一下脆 | 头不够短/不够强 | `tr_head_ms` 降、`tr_head_floor` 降 |
| 连打糊成一片 | 锁太短 | `tr_lockout_ms` 加大（70 → 90） |
| 单次冲击"只有一下"，没有余震 | 身保持太短 | `tr_body_hold_ms` 加大（150 → 200） |
| 余震拖太久，像黏住 | 释放太慢 | `tr_release_ms` 降（220 → 150） |
| 低频鼓点跑到扳机上 | 通道划分问题，不是参数 | 看 `decode_57` 的 t/l/r 是否该对调 |
| 一直有轻微"底噪震动" | 常态太硬 | `tf_base` 已经是 1；改 `tf_enable=0` |

**注意**：如果第 3 项（低频鼓点）差异明显，那不是调参能解决的，
是通道语义判断错了——这类问题只有对照真机才能发现，也最值得花时间。

## 6. 回归（改完必做）

```bash
for t in test_*.py; do python -I "$t"; done      # 应全绿
```

改参数不需要改代码，但如果动了 `decode_57` 或帧构造，回归必须全过。

## 7. 别做的事

- **不拆机**：拆了就没有第二次，且退货资格直接没了
- **不刷固件**：一刷就回不去，且可能变砖
- **不改固件**：这是"规避技术措施"的界线，跨过去性质就变了
- **不把抓包文件提交进仓库**：里面有厂商的设备描述符与私有帧
